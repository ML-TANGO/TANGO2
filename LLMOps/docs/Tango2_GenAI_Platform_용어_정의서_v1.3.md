# 📘 Tango2 GenAI Platform 플랫폼 용어 정의서 (v1.4)

> **[읽기 전 안내]** 본 용어집은 Tango2 GenAI Platform을 사용하여 AI 모델을 개발·학습·배포·평가하는 사용자를 위한 안내서입니다. 각 용어에 기재된 자원(인스턴스 등)은 플랫폼이 설치된 쿠버네티스 클러스터 환경 기준이며, 타겟 디바이스(임베디드 기기)의 물리적 자원과는 별개로 운영됩니다.
>
> **v1.4 변경 (2026-10)** — 화면 메뉴 개편 반영: '플레이그라운드'를 **배포 / 추론** 메뉴로 정리, 더 이상 메뉴에 없는 수집기·워커·오토스케일링·테스트(시뮬레이션) 용어 삭제, 평가·양자화·엣지·외부 컨테이너·데이터 파이프라인·외부 API 게시·서빙 엔진·VLM/SDS 용어 추가.

## 1. 핵심 개념 및 방법론 (Core Concepts)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| MLOps | MLOps | 데이터 수집·관리부터 모델 학습·배포·운영까지 AI 개발 전 과정(End-to-End)을 체계화·자동화하는 방법론입니다. 플랫폼은 MLOps 라이프사이클을 GUI 기반으로 제공하여 비개발자도 손쉽게 AI 서비스를 구축할 수 있도록 지원합니다. | |
| LLMOps | LLMOps | MLOps 라이프사이클을 LLM(대규모 언어 모델) 개발에 맞게 확장한 방법론입니다. 파운데이션 모델 준비 → 학습 데이터 구축 → 파인튜닝 → 프롬프트 엔지니어링 → 서비스 배포 → 평가 단계로 이루어집니다. | 플랫폼은 데이터 파이프라인 → 파인튜닝 → 양자화 → 배포/추론 → 평가 메뉴로 LLMOps 라이프사이클을 지원합니다. |
| 추론 | Inference | 학습이 완료된 AI 모델이 새로운 입력 데이터를 받아 예측 결과를 반환하는 과정입니다. 배포된 모델 API에 요청이 들어올 때마다 추론이 수행됩니다. | 추론 품질은 모델의 학습 수준과 추론 파라미터(온도, Top-P/K 등) 설정에 따라 달라집니다. **추론** 메뉴에서 실행 중인 배포를 골라 파라미터를 조정하며 결과를 확인할 수 있습니다. |
| 파운데이션 모델 | Foundation Model | 대규모 데이터로 사전 학습된 LLM으로, 파인튜닝의 출발점이 됩니다. 모델 생성 시 Hugging Face에서 원하는 모델을 검색해 불러오거나, 플랫폼에 이미 있는 모델(커밋)에서 시작하거나, 도메인(SDS) 모델로 만들 수 있습니다. | 파운데이션 모델을 그대로 사용할 수도 있고, 보유한 도메인 데이터로 파인튜닝하여 성능을 최적화할 수 있습니다. 모델마다 지원하는 언어, Context Window 크기, 라이선스 조건이 다르므로 선택 시 확인이 필요합니다. |
| 체크포인트 | Checkpoint | 파인튜닝 진행 중 특정 시점의 모델 가중치를 저장한 스냅샷입니다. [커밋] 기능으로 생성되며, 각 커밋은 독립적인 체크포인트로 관리됩니다. | 원하는 커밋(체크포인트)을 선택하면 해당 시점부터 학습을 재개할 수 있어, 처음부터 다시 학습할 필요가 없습니다. 커밋은 배포해 **추론** 메뉴에서 테스트할 수 있습니다. |
| VLM | Vision-Language Model | 이미지와 텍스트를 함께 입력받아 텍스트를 생성하는 멀티모달 모델입니다. | 배포(vLLM 엔진)에서 VLM으로 판별된 모델은 추론 시 이미지를 함께 보낼 수 있습니다. 범용 VLM의 생성·파인튜닝 선택지는 현재 비활성이며, VLM 학습은 도메인(SDS)으로 지원합니다. |
| SDS | Software Defined Ship | 해양(선박) 도메인 실증 과제입니다. 플랫폼에서는 선박 영상·AIS(선박 자동식별 장치) 데이터로 상황을 설명하고 항해 판단을 돕는 **SDS VLM**(CLIP + LLaMA-3.1 계열)을 학습·양자화·배포·평가하는 도메인을 뜻합니다. | 모델 생성 시 `Domain > SDS`로 만듭니다. 학습은 협력기관 외부 컨테이너(레시피 phase 단위 실행)로 수행되며, 체크포인트 관리·전문가 평가(AIS 표의 CPA·TCPA 등)를 지원합니다. SDM·SDF 도메인은 현재 비활성입니다. |

## 2. 인프라 및 환경 (Infrastructure & Base)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| 워크스페이스 | Workspace | 플랫폼에서 자신이 속한 작업 공간의 단위입니다. 로그인 후 워크스페이스를 선택하여 작업을 시작하며, 사용자는 동시에 여러 워크스페이스에 참여할 수 있습니다. | 워크스페이스마다 사용 가능한 GPU 등 연산 자원과 스토리지 용량이 별도로 할당됩니다. 구성원 추가·변경이나 자원 조정이 필요하면 워크스페이스 관리자에게 요청합니다. |
| 인스턴스 | Instance | 학습 또는 배포에 할당하는 GPU·CPU·RAM 자원 묶음의 단위입니다. 학습·배포 생성 시 사용할 인스턴스와 개수를 선택합니다. | 현재 사용 가능한 인스턴스 목록과 할당 현황은 워크스페이스 대시보드에서 확인할 수 있습니다. |
| 스토리지 | Storage | 데이터셋·모델 체크포인트 등의 파일을 저장하는 공간입니다. 워크스페이스 단위로 Main Storage(학습 결과물 등 일반 파일)와 Data Storage(데이터셋 전용)로 구분됩니다. | 스토리지 사용량은 대시보드에서 확인할 수 있습니다. 여러 학습에서 같은 데이터셋을 공유해 재활용할 수 있으며, 용량 추가가 필요한 경우 워크스페이스 관리자에게 문의합니다. |
| 드라이브 | Drive | 워크스페이스의 데이터셋 파일을 탐색·업로드·관리하는 화면입니다. 사이드바 상단의 [드라이브] 카드로 들어갑니다. | 데이터셋 상세에서 **포맷 변환**(CSV/TXT/Parquet → JSON/JSONL)과 SDS 데이터셋의 LLaVA 학습 형식 변환을 실행할 수 있습니다. |
| 도커 이미지 | Docker Image | 모델 학습 및 배포에 필요한 소프트웨어 실행 환경(딥러닝 프레임워크, Python 패키지 등)을 패키징한 컨테이너 이미지입니다. | 플랫폼은 파인튜닝 이미지와 서빙 엔진별 배포 이미지를 기본 제공합니다. |
| 대시보드 | Dashboard | 워크스페이스 이름·구성원·인스턴스 사용 현황·스토리지 사용량 등 워크스페이스 상태를 한눈에 확인할 수 있는 통합 화면입니다. | 워크스페이스를 선택한 뒤 사이드바 상단의 [대시보드] 카드로 들어갑니다. 진행 중인 학습·배포 현황과 남은 자원 현황을 파악할 수 있습니다. |
| 엣지 디바이스 | Edge Device | 쿠버네티스 클러스터에 합류하지 않는 단일 노드 장치로, 장치에서 동작하는 에이전트(remoteManager)를 통해 플랫폼과 연동됩니다. 관리자가 [노드] 메뉴에서 등록합니다. | 플랫폼은 에이전트에 배포 지시(`/ops`)·상태 조회(`/metrics`)를 보내고, 장치는 heartbeat 를 보냅니다. 통신 규약은 관리자 [Edge API 규격] 메뉴와 `examples/edge-agent/README.md` 에 있습니다. |
| 외부 컨테이너 | External Container | 협력기관이 제공한 학습·추론·변환·평가 컨테이너를 manifest(YAML)로 등록해 플랫폼이 직접 실행하는 방식입니다. | 플랫폼이 워크스페이스 안에 파드를 띄우고 클러스터 내부 주소로만 호출합니다. 규격: `examples/hello-plugin/external-container-spec.md`. 양자화(llama.cpp)·평가 채점기·SDS 학습/추론이 이 방식으로 동작합니다. |

## 3. 프로젝트 및 학습 (Project & Training)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| 프로젝트 | Project | 모델·배포·평가 프로젝트·데이터 파이프라인 등 각 작업을 독립적으로 관리하는 단위입니다. | 모델은 생성 시 Public(워크스페이스 내 전원 공유) 또는 Private(지정 인원만 공유)으로 접근 권한을 설정할 수 있습니다. 워크스페이스 관리자는 권한에 관계없이 모든 모델에 접근할 수 있습니다. |
| 모델 | Model | 파인튜닝 등을 통해 생성된 AI 모델 결과물로, **배포** 메뉴에서 서빙되고 **추론** 메뉴에서 사용됩니다. | 플랫폼 내에서 파인튜닝한 LLM, Hugging Face에서 불러온 파운데이션 모델, 도메인(SDS) 모델이 모두 '모델'로 관리됩니다. |
| 파인튜닝 | Fine-tuning | 사전 학습된 LLM(Large Language Model)에 특정 도메인·태스크 데이터를 추가 학습시켜 성능을 최적화하는 과정입니다. LoRA 등 PEFT 기법을 활용하여 적은 자원으로도 효율적으로 수행할 수 있습니다. | 파인튜닝 진행 중 Loss 그래프 등 학습 지표를 실시간으로 확인할 수 있습니다. [커밋]을 생성해 두면 해당 시점의 모델 상태가 저장되며, 이후 원하는 커밋 시점부터 학습을 재개할 수 있습니다. |
| 데이터셋 | Dataset | 학습 및 검증에 사용되는 데이터 묶음으로, 플랫폼 스토리지에 폴더 단위로 저장·관리됩니다. 드라이브에서 파일을 직접 업로드하거나, 데이터 파이프라인으로 학습 데이터를 만들어 추가할 수 있습니다. | 데이터셋은 워크스페이스 내 구성원 간 공유되며, 여러 학습에서 동일한 데이터셋을 재사용할 수 있습니다. 접근 권한은 읽기&쓰기 / 읽기 전용으로 구분 설정하여 원본 데이터 보호가 가능합니다. |
| 데이터 파이프라인 | Data Pipeline | 학습 데이터를 단계별로 만드는 기능입니다(**데이터** 메뉴). 업로드 → 전처리 → 필터 → 생성 → VLM 심사 → 사람 검수 → 분포 분석 → 구성·분할 → 버전 릴리스 순으로 진행하며, 각 단계는 독립 잡으로 실행되고 실행 이력이 남습니다. | 프리셋은 '범용'과 '해양 COLREG'(SDS 영상·AIS 수집·조인·COLREG 판정 단계 추가) 두 가지입니다. 실행끼리 결과를 비교할 수 있습니다. |
| 커밋 | Commit | LLM 파인튜닝 진행 중 중간 모델 상태(체크포인트)를 저장하는 기능입니다. 하나의 모델에 여러 커밋(체크포인트)이 누적되어 이력으로 관리됩니다. | 커밋된 체크포인트를 로드하여 해당 시점부터 재학습이 가능합니다. 도메인(SDS) 모델은 [체크포인트] 탭에서 목록·best 지정·삭제를 관리합니다. |
| 학습 지표 | Metrics | 모델 학습의 진행 상황과 품질을 판단하기 위한 수치 지표입니다. ① Loss – 모델 예측값과 정답 간 오차(낮을수록 좋음) ② Grad_norm – 학습 안정성 지표(급격한 증가 시 이상 신호) ③ Learning Rate – 현재 적용 중인 학습률. 학습 중 플랫폼의 시각화 기능을 통해 실시간 그래프로 확인할 수 있습니다. | Loss가 충분히 수렴하지 않거나 Grad_norm이 급격히 증가(폭발)하는 경우, 학습률·배치 크기·그래디언트 누적 등 하이퍼파라미터 조정을 검토합니다. |
| 양자화 | Quantization | 모델 가중치를 낮은 비트로 줄여 크기와 추론 자원을 줄이는 과정입니다. 플랫폼은 모델 상세의 [양자화] 탭에서 커밋을 llama.cpp **GGUF**(Q4_K_M / Q5_K_M / Q6_K)로 변환하고, 실행 스크립트와 함께 **포팅 패키지**로 만듭니다. | 온디바이스(엣지)·독립 패키지 배포는 이 GGUF 패키지가 있어야 진행할 수 있습니다. SDS(VLM) 모델은 비전 인코더 파일(mmproj)이 함께 담깁니다. |

## 4. 배포 및 운영 (Deployment & Ops)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| 배포 / 추론 | Deployment / Inference | 모델을 서빙 가능한 상태로 띄우는 **배포** 메뉴와, 실행 중인 배포를 골라 채팅·데이터셋으로 결과를 확인하는 **추론** 메뉴입니다. 예전 '플레이그라운드' 기능이 이 두 메뉴로 나뉘었습니다. | 배포 상세는 정보·모델·모니터링 탭으로 구성됩니다. 추론 화면에서는 프롬프트 최적화(최적 프롬프트 탐색 후 주입)를 함께 사용할 수 있습니다. |
| 배포 유형 | Deployment Type | 배포 생성 시 고르는 대상입니다. ① **클러스터** – 플랫폼 GPU에서 서빙 엔진으로 서빙 ② **온디바이스(엣지)** – 등록된 엣지 디바이스로 GGUF 패키지 전달·실행 ③ **독립 패키지(Standalone)** – 오프라인에서 실행할 수 있는 번들·실행 스크립트 제공 ④ **외부 LLM(API)** – 상용 API(ChatGPT·Claude·Gemini) 또는 사용자 엔드포인트를 플랫폼 배포처럼 사용 | 온디바이스·독립 패키지는 먼저 양자화가 필요합니다. 외부 LLM의 API 키는 쿠버네티스 Secret으로만 보관됩니다. |
| 서빙 엔진 | Serving Engine | 클러스터 배포에서 모델을 실제로 띄우는 추론 런타임입니다. vLLM · llama.cpp · TGI · Ollama · Triton · TensorRT-LLM 중에서 고릅니다. | 기본은 vLLM입니다. llama.cpp는 GGUF(양자화 결과)를 직접 서빙합니다. |
| RESTful API | RESTful API | 배포된 모델을 외부 서비스와 연동하기 위해 제공하는 웹 표준 방식의 API입니다. 외부 애플리케이션은 HTTP 요청을 보내 모델의 추론 결과를 JSON 형식으로 받아올 수 있습니다. | 클러스터 밖에서 호출하려면 **외부 API 게시**가 필요합니다. 게시하면 배포 상세에서 엔드포인트·API 키·요청 형식(curl 예시)을 확인할 수 있습니다. |
| 외부 API 게시 | External API Publish | 배포를 클러스터 밖에서 호출할 수 있도록 공개 경로를 열고 API 키를 발급하는 기능입니다. 키가 없는 요청은 거부되며, 요청 횟수·크기 상한이 적용됩니다. | 키 재발급(회전)과 게시 해제가 가능합니다. 게시 중인 배포를 중지하면 게시도 함께 종료됩니다. |
| 모니터링 | Monitoring | 배포된 모델 서비스의 운영 상태를 확인하는 기능입니다. API 호출 수, 응답 현황, 비정상 처리 발생 건수 등의 지표를 그래프로 시각화합니다. | 배포 상세의 [모니터링] 탭에서 운영 현황을 확인할 수 있습니다. |
| 비정상 처리 | Exception | 오류 또는 잘못된 입력 등으로 인해 모델이 정상적인 추론 결과를 반환하지 못한 API 요청 건입니다. 모니터링 화면에서 비정상 처리 건수와 기록을 확인할 수 있습니다. | 비정상 처리가 지속적으로 발생하는 경우 원인(입력 형식 오류, 자원 부족, 모델 로딩 실패 등)을 파악하고 조치합니다. |

## 🧪 부록: 세부 설정 및 파라미터 용어 정의 (학습 / 배포)

> 아래 파라미터들은 LLM 파인튜닝 및 배포/추론 사용 시 조정하는 주요 설정값입니다. 수치를 직접 입력하거나 슬라이더(Bar) UI로 간편하게 조정할 수 있습니다.

### 1. 모델 파인튜닝 기법 및 설정 (Fine-tuning)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| LoRA / DoRA | LoRA / DoRA | 전체 모델 가중치를 수정하지 않고 소규모 추가 학습 모듈(Adapter)만 학습하는 경량 파인튜닝 기법(PEFT)입니다. 일반적인 전체 파인튜닝에 비해 GPU 자원을 크게 절약하면서도 효과적으로 모델 성능을 개선할 수 있습니다. | DoRA는 LoRA의 개선 버전으로 학습 안정성과 성능이 향상되었습니다. 파인튜닝 설정에서 LoRA를 적용하여 파인튜닝을 실행할 수 있으며(베이스 모델 8-bit 로딩 옵션 포함), 추후 DoRA를 지원할 예정입니다. |
| 에포크 | Number of Epochs | 전체 학습 데이터셋을 처음부터 끝까지 한 번 학습하는 것을 1 에포크라고 하며, 지정한 횟수만큼 반복 학습을 수행합니다. 모델 상세의 파인튜닝 파라미터 설정에서 직접 입력 또는 Bar UI로 조정합니다. | 에포크 수가 너무 많으면 과적합(Overfitting, 학습 데이터에만 최적화되어 실제 사용 성능 저하), 너무 적으면 과소적합(Underfitting)이 발생합니다. 학습 중 Loss 그래프를 보며 적절한 수를 결정합니다. |
| 그래디언트 누적 | Gradient Accumulation | GPU 메모리가 부족하여 한 번에 큰 배치로 학습하기 어려울 때, 여러 번의 소규모 배치 학습 결과를 누적한 뒤 한꺼번에 모델을 업데이트하는 방식입니다. 실효 배치 크기 = 배치 크기 × 누적 스텝 수 | 메모리가 제한된 환경에서도 큰 배치 크기로 학습한 것과 유사한 효과를 낼 수 있습니다. 누적 스텝 수가 클수록 실제로는 더 많은 데이터를 모아서 업데이트하는 셈입니다. |
| 컷오프 길이 | Cutoff Length | 학습 시 입력 데이터(프롬프트+답변)의 최대 토큰 수를 제한하는 설정입니다. 이 길이를 초과하는 부분은 잘려나가며, 값이 클수록 더 긴 문맥을 학습할 수 있으나 GPU 메모리 소비가 증가합니다. | 사용하는 LLM이 처리할 수 있는 최대 토큰 수(Context Window) 이내로 설정해야 합니다. 예를 들어 Context Window가 4,096 토큰인 모델이라면 Cutoff Length를 4,096 이하로 설정합니다. |
| 학습률 | Learning Rate | 각 학습 스텝에서 모델을 얼마나 크게 수정할지를 결정하는 값입니다. 값이 작을수록 조금씩 안정적으로 학습되고, 클수록 빠르게 학습되지만 결과가 불안정해질 수 있습니다. | 일반적으로 1e-5 ~ 5e-4 범위를 사용하며, 웜업 스텝과 함께 설정하면 학습 초기 불안정을 줄일 수 있습니다. 학습 중 Loss가 급격히 오르내리면 학습률을 낮추는 것을 검토합니다. |
| 웜업 스텝 | Warmup Steps | 학습 초기에 학습률을 0에서 목표값까지 서서히 높여가는 구간의 스텝 수입니다. 처음부터 높은 학습률로 시작할 때 발생하는 학습 불안정을 방지합니다. | 전체 학습 스텝의 5~10% 수준으로 설정하는 것이 일반적입니다. 학습 초반 Loss가 비정상적으로 튀는 경우 웜업 스텝을 늘리는 것을 검토합니다. |

### 2. 모델 배포 및 추론 파라미터 (Inference)

| 용어 | 영문명 | 정의 및 상세 설명 | 참고 |
|------|--------|-------------------|------|
| 요청 / 응답 | Request / Response | 외부 애플리케이션이 배포된 모델 API로 보내는 입력(Request)과, 모델이 추론하여 반환하는 결과(Response)의 한 쌍입니다. 플랫폼의 배포 API는 JSON 형식으로 데이터를 주고받습니다. | 배포 상세의 외부 API 게시 영역에서 요청 JSON 포맷을 확인할 수 있어, 외부 서비스 연동 전 사전 검증이 가능합니다. |
| 온도 | Temperature | 답변의 일관성과 다양성을 조절하는 값입니다(범위: 0~1 또는 그 이상). 낮을수록 매번 비슷하고 안정적인 답변이 생성되고, 높을수록 다양하고 창의적인 답변이 생성됩니다. | 사실 기반 Q&A나 정형화된 답변이 필요한 경우 낮은 값(0.1~0.3), 창의적인 글쓰기·아이디어 생성에는 높은 값(0.7~1.0)을 권장합니다. |
| Top P / Top K | Top P / Top K | 모델이 다음 단어를 선택할 때 후보 범위를 제한하여 품질 낮은 답변 생성을 억제하는 필터 설정입니다. · Top P: 확률 합이 P에 도달할 때까지의 상위 후보 중에서만 선택 · Top K: 확률 상위 K개의 후보 중에서만 선택 | Top P와 Top K를 함께 사용하면 두 조건을 모두 만족하는 범위 내에서 단어가 선택됩니다. 값이 너무 작으면 답변이 단조로워질 수 있으니 온도 값과 함께 균형을 맞춰 조정합니다. |
| 반복 페널티 | Repetition Penalty | 모델이 이미 생성한 단어를 반복하지 않도록 억제하는 값입니다. 1.0은 페널티 없음(기본)이며, 값이 클수록 같은 단어·문장을 반복하기 어렵게 됩니다. | 값을 너무 높게 설정하면 문맥상 반복이 자연스러운 단어까지 억제되어 오히려 답변 품질이 낮아질 수 있으므로, 1.1~1.3 내외에서 조정하는 것을 권장합니다. |
| 최대 시퀀스 | Max Sequence | 한 번의 요청에서 모델이 생성할 수 있는 최대 출력 길이(토큰 수)입니다. 응답이 이 길이에 도달하면 생성이 중단됩니다. | 너무 짧게 설정하면 답변이 중간에 잘리고, 불필요하게 크게 설정하면 응답 시간이 길어집니다. 실제 서비스 답변 길이를 고려하여 적절한 값으로 설정합니다. |
